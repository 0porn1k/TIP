## Как запустить

Всё запускается из папки `practice-03`:

```bash
npm run check:service   # проверки функций из ПР2
npm start               # локальный сервер на http://127.0.0.1:5503/
```

В PowerShell у меня `npm` блокируется, поэтому пишу `npm.cmd start` и `npm.cmd run check:service`. Можно и напрямую: `node tools/serve.mjs`.
Пакеты ставить не нужно. Сервер останавливается через `Ctrl+C`.

- http://127.0.0.1:5503/ — приложение на общем наборе;

## Эксперименты

| № | Что ожидал | Что получилось | Почему так |

| 1 | `null` и пустой список длиной 0 | `querySelector("#absent")` → `null`, `querySelectorAll(".absent").length` → `0` | Если ничего не найдено, `querySelector` даёт `null`, и обращение к его свойству упадёт с ошибкой. `querySelectorAll` всегда возвращает `NodeList`, просто пустой — у него `length` прочитать можно. |

| 5 | думал, сработает только обработчик кнопки | три записи: `phase=1, currentTarget=lab-card` → `phase=3, currentTarget=lab-button` → `phase=3, currentTarget=lab-card`; `target` везде `lab-label` | Сначала событие идёт сверху вниз (захват, на нём висит первый обработчик карточки), потом всплывает от `span` вверх. Нажимал я на `span`, поэтому `target` — всегда он, а `currentTarget` — тот, чей обработчик работает сейчас. Кнопка — уже предок, её обработчик срабатывает на всплытии (фаза 3, а не 2). |

Пятый эксперимент и объясняет, почему делегирование вообще работает: клик по подписи внутри кнопки всплывает до `ul`, и один обработчик на списке ловит нажатия во всех карточках. Но `event.target` при этом будет `span`, а не кнопка, поэтому кнопку я ищу через `closest`.

## Как устроен код

- `task-service.js` — функции из ПР2: ничего не знают о странице, только принимают массив и возвращают результат.
- `task-selectors.js` — одна функция `getVisibleTasks`: по фильтру `all`, `pending` или `completed` возвращает новый массив, исходный не трогает.
- `task-view.js` — всё, что создаёт DOM. `createTaskElement` собирает карточку через `createElement` и `textContent` (никакого `innerHTML`), `renderTaskList` меняет содержимое списка через `replaceChildren`, `renderSummary` берёт цифры из `getTaskStats`, а `renderEmptyState` показывает или прячет сообщение о пустом списке.
- `main.js` — состояние и события. Здесь живут две переменные: `currentTasks` (полный список) и `currentFilter` (что сейчас показывать). Видимые задачи нигде не хранятся, а каждый раз вычисляются в `renderApp`.

Обработчики назначаются один раз: на `ul#task-list` и на блок фильтров. При перерисовке меняются только карточки внутри `ul`, а сам `ul` остаётся, поэтому обработчик не теряется и не дублируется.

Путь одного клика по «Выполнена»: `handleTaskListClick` → `closest("button[data-action]")` → проверка, что кнопка внутри списка и действие `toggle` или `delete` → `closest("li[data-task-id]")` → `Number(dataset.taskId)` и проверка на положительное безопасное целое → `findTaskById` → `setTaskCompleted(currentTasks, id, !task.completed)` → если `ok`, сохраняю `result.tasks` в `currentTasks`, вызываю `renderApp()` и `restoreTaskFocus`. Если не `ok`, только пишу ошибку в `#operation-message`, а массив не трогаю.

Сводку считаю по `currentTasks`, а «Показано» — по видимой выборке. Поэтому, например, в фильтре «В работе» прогресс не обнуляется.

## Ошибочные id, отладка и клавиатура

Через Elements поменял `data-task-id` у карточки id 4:

- на `777` и нажал «Выполнена» → «Ошибка: Задача с id 777 не найдена»; на «Удалить» → «Ошибка: Задача с id 777 не найдена». Сводка осталась 4 / 2 / 2 / 50.0%;
- на `4abc` и нажал «Выполнена» → «Ошибка: Некорректный идентификатор задачи «4abc»». `Number("4abc")` — это `NaN`, поэтому до сервиса дело не доходит, и в `4` строка не превращается (в отличие от `parseInt`);
- после нажатия на любой фильтр карточки заново строятся из настоящего массива, атрибут снова `4`, сообщение очищается. Данные не пострадали.

Точку останова ставил в `handleTaskListClick` на строке `const id = Number(card?.dataset.taskId);` и нажимал на подпись «Выполнена» у задачи 4:

- `event.target` — `span.action-label`, `event.currentTarget` — `ul#task-list`;
- `button.dataset.action` — `"toggle"`;
- `card.dataset.taskId` — `"4"` (`string`), после `Number` — `4` (`number`);
- `findTaskById` вернул `{ id: 4, title: "Подготовить модель задач", completed: false, priority: "high" }`;
- следующая остановка — после вызова сервиса: `result.ok === true`, в `result.tasks` четыре задачи, у id 4 теперь `completed: true`, а старый объект в `currentTasks` ещё с `false`. После присваивания и `renderApp()` сводка стала 75.0%.

Клавиатура:

- Tab идёт по порядку: ссылки в шапке → «Все» → «В работе» → «Выполненные» → «Выполнена» и «Удалить» первой карточки → кнопки следующей карточки и т. д.;
- Enter на «В работе» включает фильтр (`[4, 7]`), Space на «Выполнена» у id 4 отмечает задачу;
- в фильтре «В работе» после отметки id 4 карточка исчезает, и фокус уходит на активный фильтр, а не теряется;
- Enter на «Удалить» у id 7 удаляет задачу, фокус тоже переходит на фильтр;
- Enter на «Выполнена» у id 10 в «Все» — фокус остаётся на той же кнопке той же задачи.

## Вывод

Логика из ПР2 подключилась к странице без единой правки: всё, что нужно было дописать, — отбор по фильтру, отрисовку и обработчики.
Больше всего понимания дало различие между данными и DOM. Удалить `li` со страницы — ещё не значит удалить задачу: при следующей перерисовке она вернётся.
Поэтому любое действие идёт через функцию сервиса, новый массив сохраняется в `currentTasks`, а страница каждый раз строится из него заново.
Фильтр в этой схеме только выбирает, что показать, и ничего не удаляет.

Второе, на чём я бы сам споткнулся, — `event.target`. При клике по подписи это `span`, а не кнопка, так что без `closest` половина нажатий терялась бы.
`id` из `dataset` всегда строка, и её нужно проверить после `Number`: иначе `"4abc"` или `"777"` превратятся в тихую ошибку.
Названия выводятся только через `textContent`, поэтому разметка в названии остаётся обычным текстом.
