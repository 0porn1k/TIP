## Три уровня проверки — главное в работе

| Уровень | Где | Что ловит |
|---|---|---|
| HTML-атрибуты (`required`, `maxlength`, `min`, `step`) | браузер, **до** события `submit` | пустое поле, 1.5 в id, >100 символов при вводе |
| `validateTaskDraft` | мой код, после `submit` | пробелы вместо названия, занятый id, неверный приоритет |
| `isValidTaskList` после `JSON.parse` | `task-storage.js` | испорченные/чужие данные в хранилище |

- `required` строку из пробелов **пропускает** — для него она непустая. Поэтому нужен `trim()` в своей проверке.
- Если форма невалидна по HTML, событие `submit` вообще не возникает — мой обработчик не вызывается.

## Форма

- `event.preventDefault()` — отменяет перезагрузку страницы при `submit`.
- `new FormData(form).get("id")` **всегда возвращает строку**. Число делаю сам: `Number(raw)`.
- Пустую строку отсекаю отдельно: `Number("") === 0`, без проверки пустой id стал бы нулём.
- `validateTaskDraft(draft, tasks, editingId)` возвращает **все ошибки сразу**: `{ ok: false, errors: { id, title, priority } }` или `{ ok: true, value }`.
- Ошибки показываются у поля + `aria-invalid="true"`; при вводе в поле ошибка этого поля снимается.
- `setCustomValidity("текст")` делает поле невалидным; на `input` сбрасываю `setCustomValidity("")`.

## Редактирование

- Режим хранится в `editingId` (`null` — создание).
- `updateTask(tasks, id, title, priority)` меняет только `title` и `priority`, **`completed` сохраняется**. Возвращает новый массив (неизменяемое обновление: `map` + `{ ...task, ... }`).
- При редактировании id не вводится, берётся из `editingId`; при удалении редактируемой задачи форма сбрасывается.

## localStorage

- Хранит **только строки**: запись `JSON.stringify({ version: 1, tasks })`, чтение `JSON.parse(raw)`.
- `getItem` отсутствующего ключа → `null` (это «данных ещё нет», не ошибка).
- `getItem`/`setItem`/`removeItem` могут бросить исключение (приватный режим, переполнение квоты) → каждый вызов в `try/catch`.
- `JSON.parse` на битой строке бросает `SyntaxError` → тоже `try/catch`, иначе упал бы весь запуск.
- Успешный `JSON.parse` ≠ правильные данные. Проверяю: `version === 1`, массив, у каждой задачи типы полей, **id не повторяются** (`Set`). Одна плохая задача — отклоняется весь список.
- При любой проблеме — копия исходного набора + предупреждение. Испорченную запись не удаляю (можно посмотреть в DevTools).
- Сброс — `removeItem(storageKey)`, **не** `clear()`: у общего набора и варианта разные ключи (`tip-js-practice-04:demo` / `:variant`).
- Сохраняются только успешные add/update/toggle/delete; фильтр и режим формы — нет.
- `storage` передаётся аргументом → в проверках подставляется имитация на `Map`.

## Частые вопросы

- *Почему `localStorage`, а не переменная?* Переменная живёт до перезагрузки страницы, `localStorage` — между перезагрузками.
- *Чем `localStorage` отличается от `sessionStorage`?* `sessionStorage` очищается при закрытии вкладки.
- *Почему проверять данные после `JSON.parse`?* Хранилище может изменить кто угодно (DevTools, старая версия приложения) — это недоверенный ввод.
- *Зачем `version`?* Если формат записи поменяется, старую запись можно распознать и не использовать.
- *Почему `{ ...task }` при чтении/записи?* Чтобы не отдавать наружу ссылки на внутренние объекты и не менять исходный набор `data.js`.
