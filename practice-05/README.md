## Эксперимент с очередями выполнения

| Этап | Порядок меток | Объяснение |
|---|---|---|
| Прогноз до запуска | A, B, C, D, E, F | A, B, C — синхронные. D и E — микрозадачи, D поставлена раньше. F — таймер, выполняется последним. |
| Фактический результат | A, B, C, D, E, F | Совпало с прогнозом. |
| Прогноз с моим `then` (G) | A, B, C, D, E, G, F | G регистрируется после вызова `demonstrateAwait()`, т.е. после D и E. |
| Фактический результат с G | A, B, C, D, E, G, F | Совпало. |

- **Синхронный код:** A, B (тело async-функции до первого `await` выполняется сразу), C.
- **Микрозадачи:** D (`Promise.resolve().then`), E (продолжение после `await null`), G (мой обработчик). Они выполняются в порядке постановки, как только опустел стек.
- **Таймер с `0`:** это задача следующего цикла, а не немедленный вызов. Пока очередь микрозадач не пуста, до таймера дело не доходит, поэтому F последний.
- **Если удалить обработчик D,** порядок остальных не изменится: E и G просто сдвинутся вперёд, F всё равно последний.

## Организация кода

| Файл | Ответственность |
|---|---|
| `api/server.mjs` | Готовый учебный API (не менял). |
| `src/api-client.js` | Транспорт: `buildUrl`, `fetch`, тайм-аут/отмена, проверка статуса и `Content-Type`, разбор JSON, `ApiError`. Ничего не знает про задачи. |
| `src/task-api.js` | Предметная область: маршруты `/tasks`, `/categories`, проверка фильтров до запроса и схемы после, `loadInitialData`. |
| `src/variant.js` | Только данные варианта: `4`, `{ priority: "medium" }`. |
| `src/main.js` | Консольный сценарий (не менял). |
| `checks/own.checks.js` | Мои 8 проверок. |
| `examples/experiments.js` | Прогон всех видов ошибок и замер времени. |

- `fetchFn` передаётся в фабрику, чтобы в модульных проверках подсунуть поддельный `fetch` и получить любой ответ без сети.
- HTTP-ошибки отделены от сетевых двумя этапами: в `try` обёрнут **только** вызов `fetchFn`. Всё, что брошено после (в том числе `ApiError` вида `http`), уже не попадает в этот `catch` и не превращается в `network`.
- JSON проверяется по контракту, потому что `{"data":"не массив"}` синтаксически корректен, но приложение на нём упадёт.

## Реализация общего клиента

| Требование | Как реализовано | Проверка |
|---|---|---|
| Нормализация `baseUrl` | `new URL()`, только `http:`/`https:`, без `search`/`hash`, хвостовые `/` срезаются | client 01, 04 |
| Кодирование query | `url.searchParams.set(name, String(value))`; пропуск только `undefined`, `null`, `""` | client 02, own С3 |
| Заголовок `Accept` | `headers: { Accept: "application/json" }` | client 05 |
| Проверка `response.ok` | При `!ok` — `ApiError({ kind: "http", status, code, details, url })`, поля из `payload.error` если тело — JSON | client 08, 09, 16 |
| Проверка `Content-Type` | `includes("application/json")`, иначе `invalid-response`; для `204` → `null` до проверки | client 07, 10 |
| Разбор JSON | `await response.json()` в своём `try`, `SyntaxError` кладётся в `cause` | client 11 |
| Ограничение времени | `AbortSignal.timeout(timeoutMs)`, передаётся в сам `fetch` | client 14 |
| Внешняя отмена | `AbortSignal.any([signal, timeoutSignal])`; в `catch` сначала смотрю `signal.aborted` → `aborted`, потом `timeoutSignal.aborted` → `timeout` | client 15, own С6 |

## Доменный модуль задач

| Вызов | Результат |
|---|---|
| `getTasks()` | 12 задач: `[1, 4, 7, 10, 13, 16, 19, 22, 25, 28, 31, 34]` |
| `getTasks({ completed: false, priority: "high" })` | 3 задачи: `[4, 13, 34]` |
| `getTaskById(25)` | `{ id: 25, title: "Исправить обработку ошибок", completed: true, priority: "high", categoryId: 2 }` |
| `getCategories()` | 1 «Учёба», 2 «Проект», 3 «Организация» |
| `loadInitialData({ priority: "medium" })` | `{ tasks: [4 шт.], categories: [3 шт.], meta: { total: 4, filters } }` |

Правила проверки:

- **фильтры (до запроса):** только `completed` (boolean), `priority` (`low`/`medium`/`high`), `categoryId` (положительное безопасное целое), `q` (строка, `trim`, ≤ 100). Любой другой ключ или тип → `TypeError`, запрос не уходит;
- **задача:** `isTask` — id и categoryId положительные целые, title 1–100 символов после `trim`, `completed` — boolean, допустимый priority;
- **категория:** `isCategory` — положительный id, name 1–100;
- **коллекция:** `data` — массив, все элементы по схеме, id не повторяются (`Set`), `meta.total === data.length`;
- нарушение схемы → `ApiError` с `kind: "invalid-response"`.

## Последовательная и параллельная загрузка

Два запроса `/debug/delay?ms=200`:

| Сценарий | Запуск 1, мс | Запуск 2, мс | Запуск 3, мс | Наблюдение |
|---|---:|---:|---:|---|
| Два последовательных `await` | 408.0 | 403.8 | 404.8 | ≈ сумма задержек |
| `Promise.all` | 202.9 | 216.5 | 201.8 | ≈ максимум из задержек |

Причина: при двух `await` второй запрос даже не начинается, пока не закончился первый. В `Promise.all` оба Promise уже созданы (запросы ушли), и мы ждём их одновременно. Сам `Promise.all` ничего не «распараллеливает» — он лишь ждёт уже запущенное. В `loadInitialData` искусственных задержек нет.

## Отладка

Точки останова в `requestJson`: перед `fetchFn`, после получения `response`, перед `response.json()` и в `catch`.

| | Успешный запрос `/tasks?priority=medium` | Ошибочный `/tasks/999` |
|---|---|---|
| URL | `http://127.0.0.1:5505/api/tasks?priority=medium` | `http://127.0.0.1:5505/api/tasks/999` |
| `response.status` | 200 | 404 |
| `response.ok` | true | false |
| `Content-Type` | `application/json; charset=utf-8` | `application/json; charset=utf-8` |
| payload | `{ data: [4 задачи], meta: { total: 4, filters } }` | `{ error: { code: "TASK_NOT_FOUND", … } }` |
| `ApiError` | — | `kind: "http"`, `status: 404`, `code: "TASK_NOT_FOUND"` |

Порядок проверок в `catch` выбран специально: сначала `signal?.aborted` (внешняя отмена), потом `timeoutSignal.aborted`. Если пользователь отменил запрос, это не тайм-аут, даже если таймер сработал почти одновременно.

## Вывод

Сделан двухуровневый клиент: `api-client.js` отвечает за HTTP, `task-api.js` — за предметную область. Прошли все наборы: 18 + 26 + 13 и 8 собственных проверок.

Что я различаю:

- **Promise** — это обещание значения, а не значение; без `await` в переменной лежит объект Promise;
- **HTTP-ошибка** — сервер ответил, но статус не 2xx; `fetch` при этом **не** отклоняется, проверяю `response.ok` сам;
- **сетевая ошибка** — ответа нет вообще, `fetch` отклоняется (`TypeError: fetch failed`);
- **неверный ответ** — статус 2xx, но не JSON, битый JSON или JSON не по схеме;
- **тайм-аут** — сработал `AbortSignal.timeout`;
- **отмена** — вызывающий код сам вызвал `controller.abort()`.
