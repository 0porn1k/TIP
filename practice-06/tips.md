**Тема:** браузерный клиент к API (CRUD, состояния, гонки). Вариант 4: фильтр `priority=medium`, сценарий — создать задачу среднего приоритета, она появляется в выборке (`[1, 10, 19, 28]` → `[1, 10, 19, 28, 35]`).


## Слои (кто за что отвечает)

```text
dom-app.js ─▶ app-controller.js ─▶ task-api.js ─▶ api-client.js ─▶ fetch
 (DOM)          (состояние)         (маршруты,      (HTTP, JSON,
                                     схема)          ошибки)
```

Контроллер не трогает `document`; `api` и `view` передаются параметрами → контроллер тестируется в Node.js с подставными объектами.

## HTTP-методы и статусы

| Метод | Зачем | Тело | Ответ |
|---|---|---|---|
| `GET /tasks?…` | список | нет | 200 |
| `POST /tasks` | создать | `{ title, priority, categoryId }` | **201** + `Location` |
| `PATCH /tasks/:id` | изменить часть полей | `{ completed: true }` и т.п. | 200 |
| `DELETE /tasks/:id` | удалить | нет | **204**, пустое тело |

- `id` и `completed` при создании назначает **сервер**.
- `Content-Type: application/json` добавляю **только при наличии тела** (иначе лишний CORS preflight).
- `GET` с `body`, `PUT` → `TypeError` до запроса.
- `204` → `null`, `json()` не вызывается (пустая строка — не JSON).
- `deleteTask` требует строго `null`, иначе `invalid-response`.

## Состояния списка

`loading` → `ready` (есть задачи) / `empty` (0 задач — **не ошибка**) / `error` (+ кнопка «Повторить»).

- На время загрузки `aria-busy="true"`.
- Первая загрузка — `loadInitialData` (задачи + категории параллельно). Пока категорий нет, «Повторить» снова вызывает `loadInitialData`.

## Мутации — одна схема (`mutate`)

```text
setMutationPending(true) → запрос → notify(успех) → повторный GET с текущими фильтрами
ошибка → notify(сообщение, "error")
finally → setMutationPending(false)
```

- **Сервер — источник истины**: после изменения список заново запрашивается, локальный массив руками не правлю, `localStorage` не используется.
- Кнопки блокируются → двойной щелчок не создаст две задачи.
- Редактирование не передаёт `completed` → статус сохраняется.
- `400 VALIDATION_ERROR` от сервера → `details` показываются под полями.

## Гонка запросов — два механизма

1. `loadController?.abort()` перед новой загрузкой — старый `fetch` прерывается.
2. `sequence = ++loadSequence`, после `await` — `if (sequence !== loadSequence) return;` — даже если старый ответ всё-таки пришёл, он игнорируется.

Ошибка `aborted` пользователю **не показывается** — это штатная отмена.

## Валидация формы (`validateTaskDraft`)

- `title`: строка, 1–100 после `trim`; `priority`: `low|medium|high`; `categoryId`: из `<select>` приходит строка → `Number`, должна быть среди загруженных категорий.
- Ошибка → запрос не отправляется. Клиентская проверка — для удобства, **сервер проверяет всё повторно** (клиент можно обойти).

## Безопасность

- Название с сервера — недоверенный текст → только `textContent`, не `innerHTML`. `<img onerror=...>` отображается буквами.
- `messageForError` не показывает внутренние тексты ошибок (`Error("пароль=…")` → «Не удалось выполнить операцию.»).

## CORS

`127.0.0.1:5505` и `127.0.0.1:5506` — разные origin (разный порт). Браузер проверяет заголовки `Access-Control-Allow-*`; для PATCH/DELETE и JSON-тела сначала отправляет `OPTIONS` (preflight). Решается на сервере, `no-cors` не помогает.

## Частые вопросы

- *Чем POST отличается от PATCH?* POST создаёт новый ресурс (id даёт сервер), PATCH меняет переданные поля существующего.
- *Зачем 201 и `Location`?* Сообщить, что ресурс создан, и где он теперь находится.
- *Почему одного `AbortController` мало?* Источник (тестовый клиент, кэш) может проигнорировать сигнал и всё равно вернуть данные — нужен номер запроса.
- *Почему не `localStorage`?* Данные принадлежат API; локальная копия разойдётся с сервером.
